# ChoreoLayer 기능 현황

기준일: 2026-10-12. 이번 작업은 기존 React Native/Expo 앱에 새 IA와 UI를 적용한 버전이다. 실제 동작하는 기능, 데이터 연결이 남은 기능, 앞으로 필요한 기능을 구분한다.

## 디자인 및 화면 구성

- 기준: [Figma Wireframe](https://www.figma.com/design/SgSSBc1eQGBIzPCCSmdwQl/-ID403--UI?node-id=1-2). 홈 `12:578`, Workspace `12:659`, Analysis `34:176`, Mission `34:148`의 상세 디자인 컨텍스트와 스크린샷을 확인했다.
- 첨부된 헬스 앱의 밝은 배경, 흰색 카드, 둥근 모서리, 큰 제목과 정보 카드 구성을 반영했다. 기능은 음악·움직임 연습 앱으로 유지했다.
- 첨부된 마젠타 계열 팔레트를 반영: 기본 강조 `#B20BC2`, 밝은 배경 `#F6F4F7`, 미션 배경 `#F1DCF5`, 본문 `#261E2C`.
- 하단: **홈 / 워크스페이스 / 큰 중앙 + 새로운 시작 / 분석 / 미션**. 실제 연습 화면에서는 하단 바 대신 재생 컨트롤을 고정한다.
- 휴대폰에서는 운영체제 상태 바와 안전 영역을 사용한다. 피그마의 iPhone 상태 바·홈 인디케이터를 Android 화면에 가짜로 그리지 않는다.
- 미션 기록 아이콘은 피그마 원본을 로컬 에셋으로 포함했다. 건강 앱 참고 사진 자체를 앱의 이미지로 사용하지 않았다. 미션 그래픽은 리듬을 표현한 앱 코드 기반 그래픽이다.
- 기존 이름 ChoreoLayer를 유지했다. 최종 브랜드 이름과 전용 이미지·아이콘은 추후 확정할 수 있다.

### 기존 기능 통합

- LALAL.AI 다중 악기 분리: 9종 악기 선택, 나머지 소리 포함 최대 10개, 리드/코러스 옵션으로 최대 11개. 보컬+반주 모드도 유지.
- Demucs 모델 선택과 분리 요청 유지.
- 업로드 상태·진행률·에러·서버 작업 목록, 완료 파일 열기 유지.
- 이미 분리된 WAV/MP3 레이어 2~11개 함께 가져오기 유지.
- ArrayBuffer Blob을 생성하지 않고 Expo File로 업로드하는 수정 유지.
- 각 레이어의 볼륨 0~150%, 음소거, 솔로, 전체 볼륨, 믹스 초기화.
- 동기 재생·일시정지·탐색·전체 곡 및 분석된 구간 반복.
- 서버 분석이 있는 음악의 BPM, 8카운트, 구간 정보 유지. 분석 조회 실패 시 믹서는 계속 사용 가능.
- 베이스/킥/둘 다 선택, 진동 감도, ±300ms 싱크 보정, 워치 테스트 진동 유지.
- 믹서에서 실제 재생하는 동안만 세션 시간을 누적한다. 동작을 측정한 운동 시간이나 칼로리로 표기하지 않는다.

### 세션 및 로컬 저장

- 재생 위치, 레이어 볼륨·음소거·솔로, 전체 볼륨, 반복 범위, 누적 재생 및 레이어별 청취 시간을 저장한다.
- 5초마다 저장하고, 세션 화면 이탈·앱 비활성 시에도 저장한다. 강제 종료 시 마지막 저장 이후 약 5초의 기록은 유실될 수 있다.
- ‘저장하고 나가기’ 후 홈/프로젝트에서 같은 세션을 이어간다. ‘세션 마치고 기록 저장’은 완료 이력으로 남긴다.
- 앱이 비활성화되면 음악을 일시정지한다.
- Android 로컬 가져오기 파일은 앱 문서 폴더에 복사해 캐시 정리 후에도 사용할 수 있도록 했다.
- 네이티브는 앱 문서 폴더 JSON, 웹은 localStorage를 사용한다. 저장 실패는 화면에 안내한다.
- 서로 다른 서버의 같은 작업 ID가 충돌하지 않도록 서버 주소를 프로젝트 식별에 포함한다.
- 서버나 유료 API 없이 시작할 수 있는 **16초·120 BPM 베이스/드럼 체험 음악**을 포함했다. 앱 전용으로 합성한 음원이며 `app/scripts/generate-demo.py`로 재생성할 수 있다.

### 바로 체험하기

1. 중앙 **새로운 시작 → 체험 음악 → 워치 없이 시작하기**로 믹서를 연다.
2. **워크스페이스 → 프로젝트 → 오프라인 보관**으로 음악을 저장한다. 브라우저 새로고침 후에도 다시 재생할 수 있다.
3. **분석 → 동작 분석 스튜디오 → 공간 이동 · 샘플 → 분석 기록 저장**을 누른다. 분석 탭에 부위 비율과 공간 분포가 반영된다.
4. 영상은 선택 사항이다. 영상과 좌표를 함께 저장하면 해당 영상도 다시 볼 수 있다. **영상만 넣어서 자동으로 좌표를 추출하는 기능은 아직 없다.**
5. **미션 → 커뮤니티 체험 → 샘플 피드 불러오기**에서 좋아요·댓글을 시험한다.
6. **연결 설정**에서 기록 백업과 저장 공간을 관리한다. 브라우저 데이터/앱 데이터를 삭제하면 로컬 파일도 삭제된다.

### 좌표 JSON 형식

`version: 1`, 3~36,000개의 `frames`를 받는다. `t`는 0~3,600초의 엄격한 오름차순이며, 각 프레임에 아래 다섯 관절이 모두 있어야 한다. `x/y`는 화면 왼쪽 위를 원점으로 한 0~1 좌표, 선택적 `confidence`도 0~1이다. 0.5 미만의 신뢰도는 지표에서 제외한다. 좌표 파일 크기 제한은 12MB다.

```json
{
  "version": 1,
  "frames": [
    {
      "t": 0,
      "joints": {
        "leftWrist": {"x": 0.3, "y": 0.4, "confidence": 0.9},
        "rightWrist": {"x": 0.7, "y": 0.4},
        "leftAnkle": {"x": 0.4, "y": 0.8},
        "rightAnkle": {"x": 0.6, "y": 0.8},
        "hip": {"x": 0.5, "y": 0.5}
      }
    }
  ]
}
```

위 예시는 한 프레임의 구조만 보여준다. 실제 가져오기에는 시간에 따라 변하는 프레임이 최소 3개 필요하다. JSON의 source 필드를 신뢰하여 실제 측정이라고 표시하지 않고, 가져온 좌표로 표시한다.

| 기능 | 남은 부분 |

| 실제 커뮤니티 | 계정·서버 저장·공유·권한·신고/차단·운영 기능. 현재 로컬 체험만 구현 |
| 클라우드 동기화/미션 운영 | 로그인, 여러 기기 동기화, 서버 미션 편성·검증·보상. 현재 기기별 기록/배지 |

## 현재 필요한 작업 — 우선순위

### P0: Android 새 빌드와 실기기 검증

1. **새 개발 APK 생성/설치**: Router 등 기존 추가분에 더해 `expo-image-picker`, `expo-video`, `expo-sharing`이 추가되었다. 이전 APK에서 JS 새로고침만으로 사용할 수 없다.
2. 폰/워치의 `com.systemdesign.choreolayer` 및 동일 서명 유지. EAS에서 다른 인증서로 빌드하면 워치도 같은 인증서로 다시 서명해야 한다.
3. Android 영상 선택·촬영 권한·재생·앱 재시작·파일 삭제·공유 시트 확인.
4. 실제 Galaxy Watch 연결 → 테스트 진동 → 믹서 진동 켜기 → 탐색/반복/전경 이탈 확인.
5. 실제 LALAL.AI 키로 유료 분리 전체 경로 확인. 이번 검증에서는 유료 요청을 보내지 않았다.

### P1: 실제 움직임 분석 고도화

- 포즈 추정 모델과 실행 위치(온디바이스/서버) 결정 및 연결.
- 실제 영상·음악 타임라인 동기화와 반복 구간 비교.
- 샘플과 실제 데이터 양쪽으로 지표의 유용성 평가.

### P2: 운영·성능

## 로컬 Android 빌드 오류 복구 (2026-10-12)

맥의 기본 Java가 11로 선택되어 있고, Gradle이 SDK 경로를 찾지 못하는 상태를 확인했다. `app/scripts/android.cjs`는 설치된 JDK 17 이상과 Android SDK를 찾아 빌드 프로세스에만 적용한다. 시스템 Java 설정이나 셸 설정을 바꾸지 않는다.

```bash
cd /Users/sungwoncho/Desktop/dev/SystemDesign/app
node scripts/android.cjs --check
npm run android -- --device
```

USB 디버깅을 허용한 폰을 선택한다. 이후 실행은 `npx expo start --dev-client --lan --clear`로 개발 서버를 켜고 설치된 ChoreoLayer에서 연다. Expo Go에는 커스텀 오디오/워치 모듈이 없다.

APK만 빌드할 때는 `npm run build:android`. ARM64 폰용 개발 APK가 `app/android/app/build/outputs/apk/debug/app-debug.apk`에 생성된다. 네이티브 의존성/플러그인을 변경한 경우 먼저 `npx expo prebuild --platform android --no-install`로 반영한다. 기존 폰/워치 개발 서명은 `app/android/app/debug.keystore`를 유지한다.


복구 검증 결과: JDK 17과 Android SDK 경로를 지정한 ARM64 Android 개발 APK 빌드가 **BUILD SUCCESSFUL (3분 17초)**로 완료되었다. 새 APK는 위 경로에 생성했다. 타입 검사와 린트도 통과했다. 앞부분의 ‘APK를 빌드하지 않았다’는 최초 UI/로컬 기능 작업 당시 기록이며, 이번 오류 복구에서는 네이티브 APK 빌드까지 검증했다. 폰 설치와 실제 실행은 아직 진행하지 않았다.
